# 当前博客的参考实现规范

把参考站的结构与行为迁移到当前 Next.js 项目，保留用户自己的品牌、内容和有效链接。此 Skill 服务于本项目，不把原站的 Nuxt/Vue 实现直接当作 Next.js 代码。

## 当前约定

- 站名使用「Altria」、作者使用 Altria、标语使用「生まれつきすごい人なんていない」，头像使用用户提供的 `IMG_5614.jpg`，保留现有内容。资料与头像路径以项目根目录的 `blog.config.ts` 为准。
- 启用范围：文章首页、阅读、正文分节搜索、归档、游记、主题、三语界面与真实译文关联、Feed、SEO。关于页保留。
- 友链按 2026-10-01 用户要求移除：不保留页面、导航、配置、专用样式或 sitemap 条目，不迁移友链资料、申请说明或 OPML。参考站相关记录仅供历史研究，后续对齐不得重新引入，除非用户明确重新启用。
- 评论、碎语、娱乐收藏暂缓：不创建占位入口、不连接作者服务，不用额外 widgets 填补已移除模块。
- 保留 `/posts/…`、`/archives`、`/about`、`/rss.xml` 的访问及规范地址；已移除的 `/links` 不在保留范围。参考站路径用于研究；新增语言路由只对应真实译文。
- 用户后续明确更新优先于这些约定。当前请求只涉及某个模块时，在该模块内完成任务；加载 Skill 不等于授权整站重写、服务接入或部署。

## 工作方式

1. 从当前请求确定模块与完成标准。读取对应 references，检查本地入口和固定源码组件；本地文件可能已变化，先更新本次差距结论。
2. 做实现时，先读根目录 `AGENTS.md` 及已安装 Next.js 的相关文档。复用当前代码，保持 URL 与安全渲染；内容模型、样式、交互一起处理，避免仅画出相似外壳。新增依赖遵守项目约束，不因原站使用某个 Nuxt 插件而直接安装替代包。
3. 按模块实现并验证。视觉问题使用同状态截图与测量；行为问题使用实际交互或必要回归测试。以 [验收规则](references/acceptance.md) 中相关场景为准，未完成事项留在差距表。
4. 报告改动文件、验证证据、剩余差距。分别判断功能与视觉，注明有意个人化和暂缓内容；构建通过、三栏齐全或主观评分不足以宣称还原完成。
